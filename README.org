#+TEXINFO_FILENAME: narrate.info
#+SUBTITLE: Turn books and documents into chaptered audiobooks from Emacs
#+AUTHOR: Stephen Webber
#+TEXINFO_DIR_CATEGORY: Emacs
#+TEXINFO_DIR_TITLE: Narrate: (narrate)
#+TEXINFO_DIR_DESC: Turn books and documents into chaptered audiobooks

narrate reads EPUB, PDF, DOCX, Org, Markdown, and plain text, finds the chapters, voices the text with the speech engines you choose, and writes an M4B or MP3 with chapter marks. It runs from Emacs, with a chapter outline, auditions, voice tryouts, and background renders, and its backend also works from a shell.

It has no favorite engine. Profiles in a small TOML file name an engine, a voice, a delivery style, and an audio filter; a profile can fall back to others when it can't run, and new engines and input formats plug in without changing narrate itself.

* What it does

- Reads EPUB (table of contents), PDF (bookmarks or type size, with running headers, page numbers, and footnotes dropped), DOCX (heading styles), Org (headlines), Markdown (=#= headings), and plain text ("Chapter 3", "Part Two", "IV")
- Treats lines like =* * *= or =⁂= as scene breaks and pauses longer there
- Gives each chapter inside a part its own chapter mark, titled with its part ("Part One — The Crossing"), so a listening app can skip by chapter instead of scrubbing through a part hours long; =S= in the outline, or =split = "top"=, keeps one mark per part instead
- Voices chunks through an engine, caching each one by its text and voice, so a stopped or crashed render picks up where it left off, and changing only tempo or filter re-encodes without voicing anything again
- Waits out rate limits and daily quotas instead of failing, and never switches voices partway through a book
- Splits a passage an engine refuses down to the refused sentence and has another profile read just that sentence, logging each case
- Designs voices from a written description (on engines that support it), tries several descriptions and takes side by side, and saves the one you pick as a profile
- Lets engines on your GPU rest between chunks, so a long book can run cool and quiet
- Asks before sending a manuscript to an engine that runs off your machine

* Requirements

- Emacs 29.1 or newer
- Python 3.11 or newer
- ffmpeg, which joins the chunks, applies filters, and writes the M4B or MP3 with chapter marks
- PyMuPDF (=pip install pymupdf=), for PDFs only: it supplies text with positions, which is what lets narrate drop headers, page numbers, and footnotes
- At least one speech engine (see [[*Engines][Engines]]); the built-in =tone= engine needs nothing and is enough to try everything but the voices

* Install

** The package

Clone the repository anywhere and put it on Emacs's load path:

#+begin_src emacs-lisp
(add-to-list 'load-path "~/path/to/narrate")
(require 'narrate)
(keymap-global-set "C-c n" 'narrate-command-map)   ; any free prefix
(with-eval-after-load 'dired
  (keymap-set dired-mode-map "C-c N" #'narrate-dired))
#+end_src

Or with =use-package= and =:vc= (Emacs 30):

#+begin_src emacs-lisp
(use-package narrate
  :vc (:url "https://github.com/offgridauthor/narrate")
  :bind-keymap ("C-c n" . narrate-command-map))
#+end_src

=make info= builds the Info manual from this file; with the repository on =Info-additional-directory-list=, =C-h i= lists narrate like any other package (package managers that install from the repository do this on their own).

The Emacs side runs the backend with =narrate-python=, which defaults to a venv at =~/.local/share/narrate/venv= when there is one and =python3= otherwise. A venv keeps engine packages (and their large dependencies) out of the system Python:

#+begin_src sh
python3 -m venv ~/.local/share/narrate/venv
~/.local/share/narrate/venv/bin/pip install pymupdf
#+end_src

From a shell, =narrate-cli= in the repository runs the backend without installing anything, and =pip install .= (or =pip install -e .=) installs it as a =narrate= command.

** Profiles

Copy =profiles.example.toml= to =~/.config/narrate/profiles.toml= and edit it. It starts on the =dry-run= profile, which ticks instead of speaking, so the whole path from book to M4B can be checked before any engine is installed. =NARRATE_CONFIG=, or =narrate-profiles-file= in Emacs, points at a profiles file somewhere else; the folder it sits in is narrate's config folder.

** API keys

Cloud engines read their keys from the environment. In Emacs, =narrate-auth-hosts= also fills them from auth-source, e.g. in =~/.authinfo.gpg=:

#+begin_example
machine generativelanguage.googleapis.com login apikey password YOUR-GEMINI-KEY
machine api.speechify.ai login apikey password YOUR-SPEECHIFY-KEY
#+end_example

A variable already set in the environment wins.

* Engines

Each engine is optional; profiles whose engine can't run report themselves unavailable, and their fallbacks take over.

** tone

Built in. A soft tick per sentence at ten times the speed of speech, for checking extraction, chapters, and assembly.

** gemini

Gemini TTS through the Gemini API. Get a key from Google AI Studio and set =GEMINI_API_KEY=. Voices are Google's prebuilt ones (=voice=), or designed from a description (=design=), which narrate does once and caches in =voices.json=.

Text sent to the Gemini API leaves your machine. On Google's free tier, Google may review it and use it to improve its products, and Google asks people not to send sensitive or personal information to its unpaid services. narrate asks before a Gemini profile renders a book or auditions text you selected.

** breeze

Breeze TTS 2 through [[https://github.com/HoppouAI/Breeze-TTS-2.cpp][Breeze-TTS-2.cpp]], a local server that runs on a GPU through Vulkan (or on the CPU). Text stays on your machine. Build it into narrate's data folder:

#+begin_src sh
# Debian or Ubuntu
sudo apt install cmake ninja-build g++ libvulkan-dev glslc spirv-headers
cd ~/.local/share/narrate
git clone --recursive https://github.com/HoppouAI/Breeze-TTS-2.cpp
cd Breeze-TTS-2.cpp
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
mkdir -p ~/.local/share/narrate/models
# then download one .gguf model from the project's Hugging Face page into models/
#+end_src

- The apt packages are a compiler, CMake, and the Vulkan headers and shader compiler the GPU backend needs. A working GPU driver already supplies Vulkan itself.
- =spirv-headers= is required by ggml's Vulkan backend; without it CMake stops partway through configuring, and the build step finds nothing to compile.
- narrate looks for =build/breeze-server= and the only =.gguf= in =models/=; =server= and =model= in a profile point elsewhere.
- narrate starts the server on port 8137 when a render needs it and stops it afterwards. If a crash leaves one running, =pkill breeze-server= clears it.

Breeze's weights are licensed for research and non-commercial use, which covers listening yourself but not selling the audio. It reads English and Chinese.

Breeze designs a new voice on every call, so a book voiced straight from a description would wander. narrate designs the voice once, on a fixed reference line (=ref_line=), saves it as a cloned voice in =breeze-voices/= beside the profiles file, and reads every chunk in that voice. A different =seed= gives a different take on the same description.

** kokoro

Kokoro-82M through its Python package, on your GPU if PyTorch sees one, otherwise the CPU. Text stays on your machine.

#+begin_src sh
sudo apt install espeak-ng     # Kokoro's fallback for words outside its dictionary
~/.local/share/narrate/venv/bin/pip install torch    # the build that matches your GPU
~/.local/share/narrate/venv/bin/pip install kokoro soundfile
#+end_src

Kokoro and its dependencies may lag behind the newest Python; a venv made with an older Python (uv can fetch one: =uv venv --seed --python 3.12 ~/.local/share/narrate/venv=) avoids that. Voice files download from Hugging Face on first use. A profile's =voice= can be one voice or a weighted blend of several.

** speechify

Speechify's paid API. Set =SPEECHIFY_API_KEY= and give the profile a =voice= id from Speechify's catalog. Text leaves your machine.

See [[*Extending][Extending]].

* Use

** Commands

| command                 | does                                                         |
|-------------------------+--------------------------------------------------------------|
| =narrate-file=          | open a book's chapter outline                                |
| =narrate-dired=         | the same, for the file at point in Dired                     |
| =narrate-buffer=        | an outline of the current buffer, saved or not               |
| =narrate-region=        | an outline of the selected text                              |
| =narrate-audition=      | hear a profile read a stock passage, or the selected text    |
| =narrate-design-voice=  | create a profile's designed voice and play its preview       |
| =narrate-tryout=        | several descriptions, several takes each, side by side       |
| =narrate-keep=          | save one tryout take as a profile of its own                 |
| =narrate-gpu-share=     | how much of the time local engines keep the GPU busy         |
| =narrate-edit-profiles= | visit the profiles file                                      |
| =narrate-open-output=   | open the output folder                                       |
| =narrate-show-log=      | show a render's log                                          |
| =narrate-cancel=        | stop a render (finished chunks stay cached)                  |
| =narrate-resume=        | pick up an unfinished render where it left off               |
| =narrate-stop-playback= | stop an audition or preview                                  |

=narrate-command-map= holds them all: =f= file, =b= buffer, =r= region, =a= audition, =d= design a voice, =t= try out voices, =K= keep a take, =g= GPU share, =p= edit profiles, =o= output folder, =l= logs, =k= stop a render, =R= resume one, =s= stop playback.

** The chapter outline

Every chapter starts marked. With a prefix argument, =narrate-file= asks for the profile first.

| key   | does                                                          |
|-------+---------------------------------------------------------------|
| m u t | mark, unmark, toggle all (unmark copyright pages and indexes) |
| RET   | read the text narrate extracted for that chapter              |
| a     | hear the current profile read the chapter's opening           |
| p     | switch profile                                                |
| r     | render the marked chapters in the background                  |
| S     | switch between a mark per chapter inside parts and one per part |
| E     | export the extracted text to Org for hand cleanup             |
| g     | re-read the source after you edit it                          |
| o     | open the output folder                                        |

The header line shows the book, the profile and whether it stays on this machine (=local=) or sends text off it (=cloud=), the marked length, and the keys. Renders show progress in the mode line, like =[narrate 12% · 168/1400 chunks · 2h 10m left]=, and log to =*narrate log: TITLE*=. Finished books go to =output_dir= (=~/Audiobooks= by default), named after the book and profile, and =narrate-finished-hook= receives the path.

For PDFs, =RET= on a chapter shows what will be read. If headers, footnotes, or broken columns slipped through, =E= writes the text to an Org file; fix it there, and =narrate-buffer= in that file reads your corrections.

** Stopping and resuming

Every chunk is saved as soon as it's voiced, so a render can stop at any point without losing work. narrate remembers each render from the moment it starts until its book is written, so one stopped with =narrate-cancel=, paused at a daily quota, cut off by a crash, or left behind when Emacs closed can be picked up with =narrate-resume=: it starts the same render again, with the same book, profile, chapters, format, and output folder, and the chunks already voiced come straight from the cache. After startup, narrate mentions any unfinished renders (=narrate-mention-unfinished=), and =C-u M-x narrate-resume= forgets one instead.

Renders run as Emacs subprocesses, so closing Emacs stops them; Emacs asks first when one is running. Books are written under a temporary name and renamed when complete, so an interrupted render never leaves a half-written file that looks finished.

** Finding a voice

1. *Try.* =narrate-tryout= asks for a profile, where the descriptions come from (=tryout-designs.txt= beside the profiles file, or the profile's own =design=), and how many takes of each. The profile supplies the engine, filter, tempo, and fallbacks; the descriptions supply who's speaking. Every take reads the same passage (=tryout_text=), so takes compare the way they'd sound in a book. A line in the descriptions file can end with =| style= to try a delivery note with it.
2. *Listen.* The batch's =index.org= opens, listing the descriptions and the takes with their start times in =all.wav=, which plays every take in order. Batches stay in folders under =~/.cache/narrate/=, named by date and time.
3. *Keep.* With the cursor on a take's row in =index.org= (or its file in Dired), =narrate-keep= asks for a name and adds a profile by that name to the end of the profiles file. For Breeze it copies the take's reference clip into =breeze-voices/=, so the kept voice is the one you heard; for Gemini it records the designed voice's =voice_id=.

Gemini takes each use one of the stored voices Google allows a project (200 at the time of writing); unused ones expire.

** GPU load

Engines on the GPU (=breeze=, =kokoro=) can rest between chunks. =gpu_share= is the fraction of the time the GPU works: at 0.3, every 3 seconds of work is followed by 7 seconds of rest. =narrate-gpu-share= changes it while a render runs, and =C-u M-x narrate-gpu-share= goes back to the profiles file's setting. Resting lowers heat, fan noise, and average draw; the energy per book stays about the same. A power cap on the GPU itself (for NVIDIA, =sudo nvidia-smi -pl WATTS=) is another knob, and the two combine.

** From a shell

#+begin_example
narrate-cli profiles [--json]
narrate-cli outline FILE [--json] [--text] [--split parts|top]
narrate-cli extract FILE OUT.org [--split parts|top]
narrate-cli audition --profile NAME [--text-file F] --out OUT.wav
narrate-cli design --profile NAME --out PREVIEW.wav [--refresh]
narrate-cli tryout --profile NAME --out DIR [--designs FILE] [--takes N] [--text-file F] [--tempo T]
narrate-cli keep TRYOUT_DIR --take 01-3 --as NAME
narrate-cli render FILE --profile NAME [--chapters 1,3-5] [--out DIR] [--format m4b|mp3|mp3-split] [--split parts|top] [--no-wait]
#+end_example

=--config PROFILES.toml= goes before the command. Machine-readable events go to stdout as JSON lines, and the log goes to stderr. =--no-wait= exits with code 75 at a daily quota instead of waiting for it to reset.

* Configuration

=profiles.example.toml= documents every key. In short:

- =[defaults]= holds settings every profile inherits: the profile outlines open on, the output folder and format, tempo, gaps, loudness, =gpu_share=, and the stock passages
- each =[profiles.NAME]= table names an =engine= and whatever that engine takes, plus any of the shared keys
- =fallback= lists profiles to try when this one can't run here
- =split= in =[defaults]= decides how parts divide: ="parts"= (the default) gives each headed chapter inside a part its own chapter, and ="top"= keeps one chapter per part; =--split= on the command line and =S= in the outline override it for one book

Emacs settings are in =M-x customize-group RET narrate=. The faces =narrate-header=, =narrate-header-key=, and =narrate-header-profile= style the outline's header line.

** Files and folders

narrate follows the XDG base directory layout:

| folder                 | holds                                                               |
|------------------------+---------------------------------------------------------------------|
| =~/.config/narrate/=   | =profiles.toml=, =voices.json=, =breeze-voices/=, =tryout-designs.txt=, =plugins/= |
| =~/.local/share/narrate/= | the Python venv, Breeze-TTS-2.cpp and its models               |
| =~/.cache/narrate/=    | auditions, previews, tryouts, the Breeze server log, the live GPU-share setting |

=XDG_CONFIG_HOME=, =XDG_DATA_HOME=, and =XDG_CACHE_HOME= move them, and =NARRATE_CONFIG= puts the profiles file (and so the config folder) anywhere, such as a synced folder. A render's chunk cache lives in =.narrate-work/= inside the output folder.

* Extending

Python files in =plugins/= beside the profiles file load at startup. A plugin can add engines and input readers; =examples/plugins/= has one of each.

An engine subclasses =narrate.engines.base.Engine=, sets =name=, and implements:

- =prepare()= checks it can run here and raises =EngineUnavailable= if not
- =identity()= returns a string naming the voice exactly; it keys the chunk cache
- =synth(text)= returns 24 kHz mono 16-bit WAV bytes, raising =Refused= for text it can't voice, =Transient= for retryable failures, and =RateLimited= when asked to slow down

Class attributes tell narrate the rest: =max_chars= (chunk size), =check_length= (re-roll audio far too short or long for its text), =uses_gpu= (=gpu_share= applies), and =remote= (where text goes when it leaves the machine, shown before sending). =narrate.engines.register(cls)= makes it available as =engine = "NAME"=.

A reader is a function from a =Path= to a =narrate.book.Book=; =narrate.readers.register(".ext", func)= ties it to an extension. =narrate.book.build_chapters= turns a list of =(heading level or None, text)= pairs into chapters the way the built-in readers do.

The backend's pieces are small modules (=readers/=, =engines/=, =chunking=, =synth=, =assemble=, =commands=, =cli=), so a different front end, or a different kind of output, can reuse them.

* Privacy

- Engines that run here (=tone=, =breeze=, =kokoro=) send nothing anywhere.
- Engines that don't (=gemini=, =speechify=) send each chunk's text to their service. narrate asks before a cloud profile renders a book or auditions selected text (=narrate-confirm-cloud=); stock passages go without asking.
- Fallbacks can cross that line: a profile on this machine whose fallback is a cloud profile will send text if the local engine can't run. Keep private work on profiles whose whole fallback chain stays local.
- Keys live in the environment or auth-source, never in the profiles file.

* Troubleshooting

- A profile says it's unavailable :: =narrate-show-log= has the reason (no key, a package missing, no model, a server that didn't start). =narrate-cli profiles= lists each profile's engine and fallbacks.
- Breeze won't start :: =~/.cache/narrate/breeze-server.log= has the server's own output.
- Chapters look wrong :: =RET= in the outline shows the extracted text. DOCX chapters come from heading styles, so titles typed as bold body text won't register; =E= exports the text to Org for fixing by hand. A part only splits into chapters when its chapters have headings one level below the part's.
- No cover in the finished book :: a cover image ffmpeg can't embed is skipped, with a line in the log saying so; the audio and chapters are unaffected.
- The mode line shows no time left :: the estimate appears after a minute or so of progress, once there's a pace to measure.
- Formats narrate doesn't read :: convert first, e.g. =soffice --headless --convert-to docx file.odt= (also .doc and .rtf) or Calibre's =ebook-convert book.azw3 book.epub= (also .mobi).
